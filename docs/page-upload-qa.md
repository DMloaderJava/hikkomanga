## Осознанные ограничения и отличия API

- Чтение File требует async: detectFormat и validateFile возвращают Promise.
- Лимит страниц проверяется pdf.js до рендера, не заголовочной validateFile.
- UI использует streaming-генератор, фазы parsing/uploading чередуются постранично, чтобы не хранить до 500 готовых Blob. Исходный PDF и внутренние структуры pdf.js всё равно находятся в памяти; публичный pdfToPages по контракту собирает массив.
- Во время уже отправленного Supabase upload отмена кооперативная: запрос заканчивается, успешная страница сохраняется, следующие не стартуют. Нативное декодирование изображения не имеет AbortSignal.
- PDF-оригиналы не очищаются автоматически, в том числе после ошибки/отмены и удаления главы. Нужна ручная очистка.
- Большие GIF не сжимаются, поэтому быстро расходуют Storage. GIF с неоднозначной структурой сохраняется как есть, даже если повреждён.
- HEIF/TIFF с несколькими изображениями: используется первое. Огромные размеры декодированного изображения могут исчерпать память несмотря на лимит размера файла.
- PDF использует локальные JS fallback-декодеры без WASM; экзотические PDF-кодировки требуют отдельного QA.
- heic2any требует разрешения unsafe-eval только в заголовке его локального worker; HTML CSP остаётся строгим. После обновления библиотеки нужна проверка build-плагина и Vercel-заголовков.
